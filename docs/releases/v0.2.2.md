Streaming timeouts, readable credential filenames and two new platforms for **cpa-deepseek**, compatible with **CLIProxyAPI v8.0.0+**.

### Changes

- Stop `request-timeout` from cutting off active streams. It now bounds a whole non-streaming request, or only the opening of a stream (until the upstream status arrives). An open stream ends when silent for the new `stream-idle-timeout` (default `5m`) or after the new `max-stream-duration` (default `1h`), and the downstream error names the limit hit.
- Lower the default `request-timeout` from `15m` to `5m`, since it no longer has to cover a whole stream.
- Name new credential files after `api-keys[].name` (for example `Personal.json`), so the CPA management UI shows the configured name instead of `deepseek-key-<sha256>.json`. Credential IDs remain key-derived. The plugin never saves over an existing file in the auth directory, and falls back to the key-derived filename when CPA lists no credentials yet.
- Align configuration parsing with cpa-opencode. YAML errors report the line near the problem without echoing values, and model names and aliases need only be non-empty, unique and free of surrounding whitespace.
- Upgrade apix from v0.2.0 to v0.4.0. Gemini-format requests and streams behave as before.
- Publish Windows arm64 and FreeBSD amd64 ZIPs.

### Upgrade notes and known limits

- Existing credentials are recognized and keep their `deepseek-key-<sha256>.json` filenames. To switch one to its readable name, delete the credential and let the plugin recreate it.
- If you relied on `request-timeout` to cap the total length of streams, set `max-stream-duration` instead. Non-streaming requests that take longer than 5 minutes need a larger `request-timeout`.
- Periodic discovery updates the plugin's local snapshot. Updating CPA's published `/v1/models` list still requires reloading or reconfiguring the plugin.
- Responses requests require full input history. Independent Files, Search, Fetch and token-counting operations remain unimplemented.

### Installation

Download `cpa-deepseek_0.3.0_<goos>_<goarch>.zip` for the operating system and architecture running CPA, verify it against `checksums.txt`, and copy the root-level dynamic library into CPA's plugin directory.

ZIPs are available for Linux, macOS and Windows on amd64/arm64, and for FreeBSD amd64. Both READMEs, example configuration, license and icon source notes are included. Live inference requires a valid DeepSeek API key and sufficient account balance.

**版本更新**：`request-timeout` 不再切断仍在接收数据的流，改为只限制非流式请求整体或流的建立阶段；新增 `stream-idle-timeout`（默认 `5m`，流内两次数据之间的最长静默）和 `max-stream-duration`（默认 `1h`，单个流的最长时长），超限时下游错误会注明触发的限制。`request-timeout` 默认值由 `15m` 降为 `5m`。

新建凭据的文件名改用 `api-keys[].name`（如 `Personal.json`），管理页不再只显示 `deepseek-key-<sha256>.json`；凭据 ID 仍由 key 派生，已有凭据保持原文件名，删除后重建即可改用新名称。插件不会覆盖凭据目录中已有的文件，CPA 尚未列出任何凭据时仍使用 key 派生的文件名。

配置解析与 cpa-opencode 对齐，YAML 错误会提示行号且不回显配置值；模型名和别名只需非空、唯一且无首尾空白。升级 apix 至 v0.4.0，Gemini 格式行为不变。新增 Windows arm64 与 FreeBSD amd64 安装包。

如曾依赖 `request-timeout` 限制流的总时长，请改用 `max-stream-duration`；耗时超过 5 分钟的非流式请求需调大 `request-timeout`。插件 ID、Provider ID 和默认模型前缀不变，兼容 CPA v8.0.0+。安装与现有限制见上文及包内中英文 README。
