Credential lifecycle improvements for **cpa-deepseek**, compatible with **CLIProxyAPI v8.0.0+**.

### Changes

- Reuse existing credentials on startup and reload instead of creating duplicate files. When CPA exposes an auth directory, the plugin also checks JSON files in its subdirectories, including credentials not yet present in CPA's runtime list. Existing filenames and host-managed state are preserved.
- Automatically remove plugin-created credential files when their keys are removed from configuration. Cleanup verifies the physical record's provider and key-derived identity. Loaded credentials must be confirmed disabled before deletion; manual, malformed, foreign and symlinked credentials are left untouched.
- Allow an empty or omitted `api-keys` list. The plugin stays registered in an idle state without upstream requests or published models. Clearing the list cleans up verifiable plugin-created credentials; adding keys later resumes normal operation on reconfiguration.
- Wait for pending credential writes before rediscovery or cleanup, including writes whose caller has already timed out.

### Upgrade notes and known limits

- **Credential removal now deletes files.** Review `api-keys` before upgrading or reloading: a missing key is treated as removed, and clearing or omitting the list requests cleanup of all verifiable plugin-created credentials. Removed credentials lose their stored metadata; adding a key again creates it with defaults. Credentials still configured retain their stored state. Shutdown, upgrades and restarts do not themselves delete configured credentials.
- When keys are configured, registration or reconfiguration fails before writing if a listed DeepSeek credential's identity cannot be established, or an unlisted JSON credential file is unreadable or nonregular. Resolve the file problem and reload rather than deleting or renaming credentials to work around it.
- Cleanup needs an auth directory exposed by CPA. It remembers previously exposed directories while the plugin remains loaded, but a cold start with no exposed paths cannot discover the directory through the current SDK.
- If cleanup cannot confirm a loaded credential is disabled, or a file operation fails, the plugin logs a warning and retries on the next reload. Check the auth directory for `*.deepseek-cleanup-*` staging files if manual recovery is requested.
- Existing duplicate files are reused rather than automatically consolidated. The cleanup described above applies when their key is removed from configuration.
- Periodic discovery updates the plugin's local snapshot. Updating CPA's published `/v1/models` list still requires reloading or reconfiguring the plugin.
- Responses requests require full input history. Independent Files, Search, Fetch and token-counting operations remain unimplemented.

### Installation

Download `cpa-deepseek_0.2.3_<goos>_<goarch>.zip` for the operating system and architecture running CPA, verify it against `checksums.txt`, and copy the root-level dynamic library into CPA's plugin directory.

ZIPs are available for Linux, macOS and Windows on amd64/arm64, and for FreeBSD amd64. Both READMEs, example configuration, license and icon source notes are included. Live inference requires a valid DeepSeek API key and sufficient account balance.

**版本更新**：修复启动或重载时重复创建凭据文件的问题。CPA 暴露凭据目录后，插件会核对目录及子目录中的 JSON 文件，复用尚未进入运行时列表的凭据，并保留已有文件名和宿主管理状态。凭据发现与清理会等待未完成的写入，包括调用方已超时但宿主仍在处理的写入。

从配置移除 key 后，插件会自动删除能验证为自身创建的对应凭据文件；对于已加载凭据，必须先确认宿主中的对应文件记录已禁用才会删除。清理依据实体文件中的 provider 和 key 派生 ID，手动创建、格式异常、其他 provider 和符号链接凭据均保留。

允许清空或省略 `api-keys`：插件进入空闲状态，不请求上游、不发布模型，同时清理所有能验证为插件创建的凭据；之后添加 key 并重新配置即可恢复运行。

**升级前请核对 `api-keys`**：缺失的 key 会被视为已移除，清空或省略列表会请求清理全部可验证的插件凭据。被删除凭据的元数据不会保留，重新添加时按默认状态创建；仍在配置中的凭据保留原有状态，关闭插件、升级或重启本身不会删除这些凭据。已有重复文件不会自动合并，在对应 key 移除时才参与清理。

配置非空 key 列表时，若无法确定已列出 DeepSeek 凭据的身份，或未列出的 JSON 文件不可读、不是普通文件，插件会在写入前报错，需排除文件问题后重载。冷启动时若 CPA 未暴露凭据路径，当前 SDK 无法提供清理目录；已加载期间会记住最近暴露的目录。清理确认或文件操作失败时会告警，可再次重载重试；若日志要求手动恢复，请检查 `*.deepseek-cleanup-*` 暂存文件。

插件 ID、Provider ID、默认模型前缀和支持平台不变，兼容 CPA v8.0.0+。安装与现有限制见上文及包内中英文 README。
