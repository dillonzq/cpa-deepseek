Model alias support for **cpa-deepseek**, compatible with **CLIProxyAPI v8.0.0+**.

### Changes

- Add `models[].alias`, following CPA's `name`/`alias` convention. The alias replaces the upstream `name` in the published model ID; the model prefix still applies, and requests still send `name` upstream. For example, `{name: deepseek-flash, alias: flash}` publishes `deepseek/flash`.
- Aliases must be unique and use the same characters as model names. An aliased model whose public ID matches another model's ID is excluded, and the plugin logs a warning on startup, reconfiguration, or when a background refresh changes the set of excluded models.
- Because aliases are applied by the plugin rather than CPA's alias layer, an alias may differ from the upstream name only in letter case, for example to share one model ID with another provider that publishes a differently cased name.

### Upgrade notes and known limits

- Configuration without `alias` is unchanged from v0.2.0.
- After an alias is set, the original public ID (for example `deepseek/deepseek-flash`) is no longer published. Update clients that request it.
- Periodic discovery updates the plugin's local snapshot. Updating CPA's published `/v1/models` list still requires reloading or reconfiguring the plugin.
- Responses requests require full input history. Independent Files, Search, Fetch and token-counting operations remain unimplemented.

### Installation

Download `cpa-deepseek_0.2.1_<goos>_<goarch>.zip` for the operating system and architecture running CPA, verify it against `checksums.txt`, and copy the root-level dynamic library into CPA's plugin directory.

ZIPs are available for Linux amd64/arm64, macOS amd64/arm64 and Windows amd64. Both READMEs, example configuration, license and icon source notes are included. Live inference requires a valid DeepSeek API key and sufficient account balance.

**版本更新**：新增 `models[].alias`，沿用 CPA 的 `name`/`alias` 约定，用别名替换对外发布 ID 中的上游 `name`；前缀仍会叠加，请求上游时仍发送 `name`。例如 `{name: deepseek-flash, alias: flash}` 发布为 `deepseek/flash`。

别名必须唯一；若加别名后的对外 ID 与其他模型的 ID 相同，该模型会被排除并记录警告日志。别名由插件发布，不经过 CPA 的别名层，因此可以只与上游名大小写不同，便于和其他发布同名模型的提供方合用同一个模型 ID。

未配置 `alias` 时行为与 v0.2.0 相同；配置别名后原对外 ID 不再发布，请同步更新客户端。插件 ID、Provider ID、默认模型前缀和支持平台不变，兼容 CPA v8.0.0+。安装与现有限制见上文及包内中英文 README。
